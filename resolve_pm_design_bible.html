Phase 1
Brand Identity
The foundational personality of Resolve PM — what the brand believes, how it feels, and why every decision flows from this core.
Brand Personality Keywords
Controlled
The ECG pulse in the logo signals urgency that is always managed — never chaotic. The platform deals with high-stakes operations but presents them calmly.
Operationally Aware
Resolve PM sees everything. Its visual language communicates intelligence — surfaces that feel like they're monitoring, not just displaying.
Executive
Decision-makers live here. Every element must convey authority and precision — nothing decorative, nothing casual.
Precise
Enterprise work is about accuracy. Typography, spacing, and data presentation must be surgical. No ambiguity.
Trustworthy
People stake their careers on this data. The platform must never look unstable, experimental, or uncertain.
Purposeful
Every pixel serves a function. The brand is not decorative. Visual weight implies operational weight.
Core Design Principles
P1
Calm at Scale
A platform used 8 hours/day must never create anxiety through its visual design. Density is acceptable; visual noise is not. Breathing room prevents cognitive fatigue.
P2
Information Before Decoration
No visual element exists unless it carries information or enables action. Background textures, gradients for aesthetics, and decorative icons are prohibited.
P3
Hierarchy Through Restraint
Emphasis works because most elements are de-emphasized. If everything is bold, nothing is. Primary actions must earn their prominence.
P4
Consistent Vocabulary
One button style. One card style. One table style. Uniformity across 200+ screens is not a constraint — it is the feature. Consistency reduces learning load.
P5
Dark is Primary
The platform commits fully to dark mode as its native state — not as an option. This reduces eye strain for long sessions and creates a premium, focused environment.
P6
The Pulse is Alive
Resolve PM monitors live operations. Motion, status indicators, and real-time data should feel alive but never frantic. The ECG metaphor guides all animation.
Phase 2
Visual Direction
What emotional register does Resolve PM occupy? The answer determines every macro design decision.
Direction Verdict
Resolve PM is: Enterprise — with Operational Intelligence Character
Not purely Financial (too austere, no operational warmth). Not Government (too bureaucratic). Not Startup (too casual, damages credibility). Not Industrial (too mechanical).

The closest analog is the mission control room aesthetic — high information density, professional dark environment, status-forward, with clear operational hierarchy. Think Bloomberg Terminal meets Linear. Sophisticated, fast, and alive.
Why Not the Others
❌ Startup / Modern SaaS
White backgrounds, bright accent colors, rounded everything — this is Notion, Linear, Figma. Resolve PM is not building productivity tools. It is running company operations. The stakes are different. The visual register must reflect that.
⚠ Technical / Developer Tool
The current UI leans too far into this — monospace labels, terminal aesthetics, PROBE_01 identifiers. This is the correct direction to borrow from, not to fully inhabit. It should feel precise, not like a command line.
✓ Enterprise Operations Intelligence
Dark, composed, data-forward. Calm default state. Visible hierarchy. Status colors that mean something. Motion that communicates operational pulse, not decoration. This is where Resolve PM lives.
Phase 3
Design Philosophy
The single guiding question that every design decision must answer.
"After 8 hours in Resolve PM, the user should feel informed and in control — not drained."
This is the north star. Every decision is tested against it.
What This Means for Design
→
No cognitive taxation without payoff
Dense data is acceptable. Visual complexity without information value is not. Every chart, badge, and label must earn its place by answering a question the user actually has.
→
Status should be instantly readable
A user scanning a project list must understand what is healthy, at risk, and blocked within 3 seconds. Color, iconography, and layout must support this without requiring reading.
→
The interface should recede
The interface itself should become invisible after familiarity. The user should be thinking about their work, not the UI. This is achieved through consistency, predictability, and restraint.
→
Actions should feel safe
Destructive actions require confirmation. Reversible actions should be clearly reversible. The platform manages critical business data. Users must never feel like they're guessing.
Phase 4
Typography System
A single font family. Strict roles. No freelancing on font sizes.
Font Family Decision
Primary: Inter (v4) — Fallback: system-ui, -apple-system, sans-serif
Rationale: Inter was designed for screens. It is neutral at small sizes, readable at high density, and carries no aesthetic personality that competes with the product. It scales from 10px monospace labels to 32px page titles without personality shifts. The variable font axis allows precise weight control.
Mono: JetBrains Mono — for all technical labels, timestamps, IDs, code
Status timestamps, AES identifiers, connection strings, database values. Never use monospace for navigation or prose. Rationale: the current UI uses mono for operational indicators — this is correct and should be systematized, not reduced.

Typography Rules
R1
All-caps labels are rationed to 3 uses per page
Currently overused. Reserved for: table column headers, section overlines, and technical status codes only.
R2
Never use font weight below 400 in the application
Dark backgrounds make thin weights unreadable at small sizes. Minimum 400 everywhere.
R3
Metric numbers use tabular figures (font-variant-numeric: tabular-nums)
Dashboard numbers must not shift width as values change. Tabular numerals ensure stable column alignment.

Phase 10–11
Iconography & Component Language
One icon library. Strict usage rules. Component philosophy without implementation.
Icon Library Decision
Library: Lucide Icons — outline only, 1.5px stroke
Rationale: Lucide is the most consistent outline icon library available. Clean geometric forms. Designed at 24px, scales to 16px without artifacts. No filled variants — mixing outline and filled icons in the same product is prohibited. The consistency of the outline style reads as precision and professionalism.
Icon Usage Rules
Sizes
16px (inline/nav), 18px (buttons), 20px (standalone), 24px (empty states only)
Stroke width
1.5px at all sizes. Never 2px. Thicker strokes at small sizes feel heavy.
Color
Icons inherit text color of parent. Never independently colored unless conveying semantic status.
Paired with text
8px gap between icon and label. Icon left of label always. Never icon-only for primary actions.
Semantic icons
Status icons (check, x, alert-triangle, info) may carry semantic color (success/danger/warning/info).
Navigation icons
Fixed icon per section. Never change. Active state: color shifts to primary, not icon change.
Prohibited
No emoji as icons. No filled icon variants. No custom SVG icons that don't match Lucide stroke weight.
Component Language Philosophy
Buttons
Three variants: Primary (filled indigo), Secondary (bordered), Ghost (text-only). One primary per view. Never more than two button variants in the same context.
Inputs
Single input style. Dark surface background, border on all four sides, indigo focus ring. No floating labels — always above the field. Error state: red border + message below.
Cards
One card style: surface-1 background, 1px border, 8px radius. No drop shadows on cards. Elevation through background lightness, not shadow. No card hover effects that lift or scale.
Tables
Fixed header. Row separator only (no vertical grid lines). Alternating row highlight optional for dense tables. Column headers in UPPERCASE 11px. Actions right-aligned.
Badges / Tags
Always semantic: color encodes meaning, never style. Text + colored background. 4px radius. Never gradient. Width constrained to content. No decorative badges.
Dialogs / Modals
Max width 640px. Title + close button in header. Action buttons bottom-right, right-aligned. Destructive action left-aligned. Backdrop: 60% opacity overlay. No animations except fade + 4px translateY.
Navigation
Left sidebar: fixed 220px. Icon + label. Active: indigo left border + subtle indigo background tint. No active icon change. Section groups separated by 4px gap.
Metrics / KPIs
Large number (28px, 500 weight). Label above in 11px uppercase muted. Delta indicator below. Trend sparkline optional. Never more than 6 KPI cards per row.
Charts
Minimal axes. No chart border. Gridlines: 1px, 15% opacity. Legend always present for multi-series. Tooltip on hover. Empty state: inline message, never a spinner.
Kanban
Column headers in surface-2. Card: white title, secondary meta. Status badge on card. Priority indicator: left border color. No card shadows. Drag state: 4px opacity reduction of source.
Command Palette
Full-width, centered, 640px max, 480px max-height. Groups with uppercase labels. Keyboard hint right-aligned. Active item: indigo tint background, no border.
Empty States
20px Lucide icon, centered. 16px title (500 weight). 14px description (muted). One CTA button. No illustrations. No emoji. Background matches surrounding surface.

Full width table. Filter bar above. Toolbar right-aligned (Add button, view toggles). Detail panel slides in from right on row click — never navigates away.

→

Full horizontal scroll. Fixed column width (280px). Header row sticky. No page padding—columns extend to edges.
Dashboard Philosophy — The Three Questions
Zone 1 — What happened?
KPI metrics, trend deltas, activity feed. Positioned top of page. Answers the operational status at a glance. Maximum 6 metrics. Each metric shows: current value, delta from previous period, trend direction.
Zone 2 — What requires attention?
At-risk items, overdue tasks, blocked projects, pending approvals. Visually distinguished — amber/red semantic colors. Never buried below the fold. This zone earns its position because it drives decisions.
Zone 3 — What should I do next?
Recommended actions, AI suggestions, quick-access shortcuts. Positioned after the user has context. Never the first thing on screen. The platform earns the right to recommend after it informs.
Phase 14–15
Accessibility & Dark Mode
WCAG AA compliance is non-negotiable. Dark mode is designed independently, not inverted.
Accessibility Requirements
👁
Contrast — WCAG AA minimum
All body text: ≥4.5:1. Large text (18px+): ≥3:1. UI components and focus indicators: ≥3:1. The defined color pairs in this system all meet these ratios. Primary (#4F6DFF) on surface-1 (#151829): 4.7:1 ✓
⌨
Keyboard Navigation
Every interactive element reachable by Tab. Focus order follows visual order. Skip-to-content link present. Command Palette (Ctrl/Cmd+K) is the primary keyboard shortcut for all navigation.
◻
Focus States
All focused elements: 2px indigo (#4F6DFF) outline + 2px offset. Never outline:none without a visible replacement. Focus ring must be visible in both light and dark contexts.
📢
Screen Readers
All icons have aria-label or aria-hidden. Status changes announced via aria-live. Tables have proper thead/th with scope. Modals trap focus and restore on close.
↔
Reduced Motion
@media (prefers-reduced-motion: reduce) removes all transitions, animations, and skeleton pulses. Charts render statically. Skeleton states become static placeholders.
🔁
Error Recovery
Form errors: inline message below field, aria-describedby linking field to error. Focus moves to first error on submit. Error messages describe what to do, not just what went wrong.
Dark Mode — Independent Design, Not Inversion
❌ Do Not Invert
surface-3 #FFFFFF
surface-2 #F4F5FA
surface-1 #ECEEF5
✓ Dark Primary
surface-3 #1F2438
surface-2 #1A1E30
surface-1 #151829
→
Charts in dark mode
Chart gridlines: 1px rgba(255,255,255,0.06). Axis labels: text-muted (#6B7494). Chart backgrounds: transparent. Data colors remain identical between light and dark — they are semantic, not surface colors.
→
Borders in dark mode
Two border strengths: border (#1E2440) for standard, border-strong (#252B45) for emphasis. Borders are additive — they define structure, not decoration. Never use box-shadow to simulate borders.
→
No pure black (#000000)
Pure black creates harsh contrast that reads as broken on modern displays. The darkest surface (#080A16) has a blue tint that connects to the indigo brand system.

Phase 18–20
Enterprise UX Rules & Implementation
The non-negotiable rules that enforce consistency at scale, and the order to implement everything.
Enterprise UX Rules — The Non-Negotiables
One Button Style per context
Primary (indigo filled) for the one primary action. Secondary (bordered) for supporting actions. Ghost for tertiary. Never create page-specific button variants. Never use gradient buttons.
One Card Style
surface-1 background. 1px border. 8px radius. 16px padding. No exceptions. No "special cards" with unique shadows, gradients, or colored backgrounds for decoration.
One Table Style
Fixed header. Row separators only. 40px row height for standard density, 32px for compact. Actions right-aligned. No zebra striping by default — only enable for very dense tables (>12 columns).
One Modal Style
Max 640px width. Standard header/body/footer structure. Primary action bottom-right. Cancel left of primary. Destructive action bottom-left. The teal modal gradient accent in current UI is eliminated.
One Form Style
Label above field. Full-width inputs. Helper text below. Error message below (red, 12px). No floating labels. No inline editing as default — only after explicit "Edit" mode activation.
One Navigation Style
Sidebar: section groups, icon + label, indigo left-border active. No nested navigation beyond 2 levels. Top subnav bar for within-section tabs only (exactly as current — this pattern is correct).
One Empty State Style
Lucide icon (24px, muted). Title (15px, 500). Description (13px, muted). One CTA. Centered. No illustrations. No emoji. This applies to tables, boards, calendars, and all list surfaces.
One Loading Style
Skeleton placeholders that match the layout of the loading content. Never a spinner centered on a page. Spinners only in buttons (inline loading) and small contained components.
Color is always semantic
No color used purely for visual interest. Every color choice communicates state, priority, status, or role. If the color carries no information, it is removed.
No modal-on-modal stacking
Modals never spawn secondary modals. If a confirmation is needed from within a modal, use an inline destructive confirmation pattern within the same modal. Never stack.
Implementation Order
1
Design Tokens → CSS custom properties file
All colors, spacing, typography, radius, shadow, motion tokens. This file becomes the single source of truth. Every component references only these tokens — never hardcoded values. Duration: 1–2 days.
2
Tier 1 Primitives → component library
Button, Input, Badge, Avatar, Tooltip, Skeleton, StatusDot. These are the atoms. All other components depend on them. Duration: 1 week.
3
AppShell → Sidebar + Header rebuild
The container that wraps everything. Fix the sidebar active states (eliminate teal, unify to indigo). Standardize the top subnav pill pattern across all sections. Duration: 3–4 days.
4
Tier 2 Composites → Card, Modal, Table, Form
The four most-used patterns. Once these are correct and consistent, 70% of pages are automatically improved. Eliminate the teal modal accent. Duration: 1 week.
5
Dashboard → Mission Control rebuild
Implement the three-zone philosophy. KPI row, attention zone, recommendation zone. This is the highest-visibility surface and the first thing users see. Duration: 1 week.
6
Tier 3 Complex → DataTable, Kanban, Calendar, Charts
Page-by-page rebuild in order of usage frequency. Execution section first (most used), then Company, Finance, Admin. Duration: 2–4 weeks.
7
Polish pass → Motion, Empty States, Loading, Accessibility audit
After all layouts are correct, add the motion layer. Audit every empty state. Run keyboard navigation test. Check all contrast ratios. Duration: 1 week.
